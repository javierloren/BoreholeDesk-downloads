# Verification and current limits

The first-release focus is a reviewed field-document/core-photo-to-borehole-and-report
workflow on a local computer. A list of modules or a test count is not professional acceptance.

| Area | Current evidence | Remaining limits |
| --- | --- | --- |
| Project data | Validation, rejected inconsistent edits, atomic saves, previous-save recovery and save/reopen tests | Independent user acceptance and large-campaign testing |
| Logs and reports | Frozen synthetic borehole, independent-process save/reopen and report checks | Broader template approval and measured physical print scale |
| RQD arithmetic | Inclusive 10 cm boundary, physical calibration and interval-weighted regressions | Independently measured field-photo RQD references and fracture interpretation |
| OCR/handwriting | Local EN/ES readers, original/reviewed text and deliberate application of intervals | Unseen handwriting authors, numeric correctness benchmarks and calibrated confidence |
| Specialist calculations | Named methods and reference regressions | Independent acceptance of each method and its domain |
| Delivery | Component hashes and local Windows installation/repair/uninstall tests | Publisher signing, anonymous delivery verification and clean Windows acceptance |

Free local processing, reviewable assistance and inspectable data/methods are our
product direction. We do not claim that individual features are unique to BoreholeDesk.
Future reliability claims will need measured correction effort, remaining errors
and final RQD agreement on reference material, not just successful demonstrations.
